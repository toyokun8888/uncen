# 要件定義

現時点で決まった範囲の要件を記録する。

## 目的

複数サイトからスクレイピングしたマスター情報をDB化し、そのマスターをもとにローカル所持ファイル、保存場所、未所持、DL可能リンクを管理する。

最終的にはブラウザで所持リストや未所持リストを確認でき、複数マスターをタブなどで切り替えられるようにする。

## 背景

既存プロジェクトはFC2中心で、DB、スクレイピング、サムネイル、所持確認、UI、PM2運用まで育っている。

ただし、機能追加のたびにルート直下へスクリプトや資料が増え、メンテナンスが難しくなっている。

新プロジェクトでは、同じ便利さを保ちつつ、最初から責務を分けて拡張しやすくする。

## 機能要件

- 複数サイトに対応できる構造にする。
- まずは1サイトのプロトタイプを完成させ、その後拡張する。
- サイトごとの取得処理は分ける。
- DB投入、ログ、CSV、run管理、dry-run、retryなどは共通化する。
- マスターDBを作成する。
- マスターをもとに所持ファイルと保存場所をDBに記録する。
- ブラウザで所持リストを表示できるようにする。
- 未所持でもDL可能リンクがあるものは表示・利用できるようにする。
- 複数マスターをブラウザ上で集約し、タブなどで切り替えられるようにする。

## 非機能要件

- ローカル完結を優先する。
- 既存DBと混ぜない。
- DB破壊リスクを避ける。
- 手動実行と自動実行の両方に対応する。
- 大量データを前提に、ログ、進捗、再開、失敗追跡を重視する。
- 将来のPM2運用を前提にする。
